今天把之前写的《深入解析 Redis 分布式锁与 Redlock》重新整理了一遍。

重新过稿的时候发现一个自己最初理解不到位的地方:**锁的过期时间到底应该怎么设**。设短了,业务还没执行完锁就被释放了;设长了,持有方宕机后其他节点要等很久。之前我只记住了"要用看门狗续期",但没想清楚续期机制依赖的是什么——本质上是客户端自己起一个定时任务,只要业务还在执行就不断延长过期时间,而 Redisson 已经把这个机制封装好了。

另外补了一个容易忽略的点:释放锁时必须校验锁的持有者(用 Lua 脚本原子地"判断是自己的锁再删除"),否则 A 超时后 B 拿到锁,A 执行完却把 B 的锁删了。

这些内容都已经更新到正式文章里了。整理旧知识的过程比想象中有收获——很多当初"背下来"的结论,这次是真正想明白了。
